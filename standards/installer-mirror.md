# installer-mirror

Значение скилла, которое установщик держит копией, совпадает с оригиналом — со значением в скрипте скилла и в его
compose-файле.

Установщик `bin/ai-dev.mjs` идёт под Node и скрипты скиллов под Bun не импортирует: Node не стирает типы у файлов в
`node_modules`, а npx запускает установщик оттуда. Поэтому установщику нужна копия: имя прокси `task-env` — чтобы
`check -g` спросил Docker о нём, имена compose-файла — чтобы `check` проекта не запускал bun там, где файла нет.
Расхождение молчит: имя файла только в списке скрипта — `check` не запускает проверку изоляции и не говорит об этом;
другое имя прокси — `check -g` называет работающий прокси незапущенным.

Общий файл данных вместо копий не помогает: имя прокси в compose-файле записано значением по умолчанию подстановки
`${AI_DEV_PROXY:-…}`, файл данных Compose не прочтёт — копия и её проверка там остаются при любом источнике (#403,
вопрос 1).

## Правило

Копия — константа установщика `const X = <литерал>;` под JSDoc с меткой `@mirror <файл> <имя>` на каждый оригинал:

- `skills/<скилл>/scripts/<скрипт>.ts <экспорт>` — экспорт скрипта скилла, значение сравнивается целиком;
- `skills/<скилл>/…/compose.yaml <переменная>` — значение по умолчанию `${<переменная>:-…}`, каждое вхождение;
  комментарии не в счёт.

Метка без константы-литерала под ней — нарушение, а не пропуск. Копия, у которой потеряли метку, выпала бы из реестра
молча — известные копии названы поимённо: `COMPOSE_FILES` и `PROXY`. Скрипт под Bun (дашборд) значение скилла
импортирует, а не копирует.
