# spec-doc

Скрипт `spec-doc` скилла `spec`: документация `docs/spec` из отчётов раннеров — дерево `tests/`, названия
тестов и их JSDoc.

Требование существует, пока есть проверяющий его тест, поэтому документацию о поведении не пишут руками: её
собирают из тестов, и разойтись с ними она не может. `docs/spec` коммитится вместе с PR, CI проверяет, что
она не отстала.

это сигнал перенести, а не ошибка разбора.

- ✅ tests/lib пропускается, тесты вне дерева — в раздел «Вне дерева»

## Проза из JSDoc

Отчёты раннеров комментариев не несут — прозу `spec-doc` берёт из исходников тестов тем же сканером, что
`spec-diff`. В документацию идёт только JSDoc; `//` — комментарий для читателя кода.

- ✅ JSDoc в начале файла — абзацы под заголовком capability, первый — описание в индексе; теги не идут
- ✅ JSDoc перед describe — абзац под подзаголовком, перед it — цитата под строкой теста
- ✅ `//`-комментарий и JSDoc, отделённый от вызова кодом, в документацию не попадают
- ✅ JSDoc вплотную к describe в файле без импортов — проза describe, а не capability
- ✅ описание capability из двух файлов — абзацы по порядку путей, в индексе — первый
- ✅ нет исходника (отчёт с другой машины) — документация без прозы, не ошибка
