# Параллельные чекауты: свой порт, своя база, общий `.git/config` к разделу «Субагенты и worktree»

Справочник к разделу «Субагенты и worktree» `AGENTS.md`: здесь правило
целиком, фрагменты и проверки. Общий конфиг git — раздел «Общий
`.git/config`» в конце.

## Правило

**Параллельные чекауты делят порты и базы.** Сервер и e2e каждого
worktree — на своём порту и своей базе; порт и подключение к базе — из
переменных окружения, а не зашиты в конфиг раннера: жёсткий порт с
`reuseExistingServer` молча берёт сервер соседа, и тесты идут против
чужого кода и чужой базы. С портом переезжает всё, что строит абсолютные
ссылки: базовый URL приложения, колбэки внешних сервисов и эмуляторов.
Занятый порт не гашу: сначала владелец —
`lsof -ti tcp:<порт> -sTCP:LISTEN` и cwd процесса; чужой — беру другой
порт. Фрагмент конфига, чек-лист «что переезжает» и своя база — ниже.

Поведение `webServer` сверено с документацией Playwright («Web server»,
`TestConfig.webServer`): `reuseExistingServer: false` падает, если на `url`
уже кто-то слушает; `env` ложится поверх `process.env`.

## Конфиг раннера: порт из окружения

```ts
// playwright.config.ts — без PORT (CI) всё на прежнем 3000
import { defineConfig } from '@playwright/test';

const port = Number(process.env.PORT ?? 3000);
const baseURL = `http://localhost:${port}`;

export default defineConfig({
  use: { baseURL },
  webServer: {
    command: `npm run dev -- --port ${port}`,
    url: baseURL,
    reuseExistingServer: false,   // занятый порт — ошибка, а не чужой сервер
    env: {
      APP_URL: baseURL,           // всё, что строит абсолютные ссылки, —
      NEXTAUTH_URL: baseURL,      // на тот же порт (чек-лист ниже)
    },
  },
});
```

`reuseExistingServer: !process.env.CI` из шаблона Playwright вне CI молча
берёт сервер соседа на том же порту: тесты идут против чужого кода и чужой
базы. На порту уже свой сервер, поднятый руками, — раннер упадёт: погасить
его, раннер поднимет свой.

## Свободный порт

```bash
for p in $(seq 3000 3099); do lsof -ti tcp:$p -sTCP:LISTEN >/dev/null || { echo $p; break; }; done
```

Два чекаута взяли один порт одновременно — второй раннер упадёт на
`reuseExistingServer: false`, а не уйдёт на чужой сервер.

## Что переезжает с портом

- `use.baseURL`, `webServer.url` и порт в команде старта сервера.
- Базовый URL приложения: `APP_URL`, `NEXTAUTH_URL` / `AUTH_URL`, `ORIGIN`
  (SvelteKit), публичные `NEXT_PUBLIC_*_URL`, `VITE_*_URL`,
  `NUXT_PUBLIC_*`. Публичные переменные вшиваются при сборке: прогон по
  собранному приложению — пересобрать с новым портом (что вшивается у
  какого фреймворка — `docs/testing.md`, «Фреймворк: три вопроса»).
- Колбэки и редиректы: OAuth redirect URI, вебхуки, ссылки в письмах.
- Эмуляторы и вспомогательные сервисы, которые поднимает прогон (почта,
  платежи, хранилище): свой порт у каждого и адрес в переменных приложения.
- Проверка: старый порт нигде не остался —
  `grep -rn "localhost:3000" .env* playwright.config.*`.

## Чей сервер на порту

```bash
lsof -nP -iTCP:3000 -sTCP:LISTEN                    # PID и команда
lsof -a -p <PID> -d cwd -Fn | sed -n 's/^n//p'      # cwd — чей это чекаут
```

cwd — свой worktree: гасить можно. Чужой — не трогать (`kill` по порту
обрывает чужой прогон), взять другой порт.

## Своя база на прогон

Общая dev-база стоит на миграции того, кто накатил последним, её контейнер
перезапускают соседи. Прогону — свой контейнер на случайном порту:

```bash
docker run -d --name e2e-db-<задача> -e POSTGRES_PASSWORD=postgres -p 127.0.0.1::5432 postgres:17-alpine
docker port e2e-db-<задача> 5432                    # → 127.0.0.1:55261
until docker exec e2e-db-<задача> pg_isready -h 127.0.0.1 -U postgres -q; do sleep 1; done
```

`pg_isready` — по TCP (`-h 127.0.0.1`): через сокет он отвечает «готово»
ещё во время initdb, и миграция упадёт на перезапуске сервера.

- Адрес — во **все** переменные подключения: `DATABASE_URL`, `DIRECT_URL`,
  `SHADOW_DATABASE_URL`, `PG*` — какие читает проект. Одна забытая уводит
  миграции или сиды в общую базу.
- Миграции и сиды — своей ветки, на эту базу, до старта сервера.
- После прогона или мержа — `docker rm -fv e2e-db-<задача>` (раздел «Git, PR
  и мерж»: временные ресурсы сессии). `-v` удаляет и анонимный том с
  данными базы: без него том остаётся висеть.
- **`docker compose down -v` — не делать.** Тома compose общие для всех
  чекаутов, если имя проекта задано не каталогом (`name:` в compose-файле,
  `COMPOSE_PROJECT_NAME` в скопированном `.env`) или у тома явное `name:` /
  `external`: `down -v` в своём worktree стирает базу главного чекаута и
  соседей. Чистая база — свой контейнер, как выше.

## Общий `.git/config`

Все worktree репозитория — и главный чекаут — читают один `.git/config`:
у копии свои `HEAD`, индекс и рабочие файлы, а конфиг, хуки и ветки общие.
`git config user.name` или `user.email` в любой копии меняет автора
коммитов всем сессиям репозитория, а не своей. Хостинг может не выкатывать
коммит автора без доступа к проекту: деплой не идёт, и сайт незаметно
отстаёт от `main`.

- **В копиях и в заданиях субагентам — никаких `git config`:** ни
  `--local`, ни `--global` (тот меняет все репозитории машины), ни
  `--worktree`: без `extensions.worktreeConfig` он пишет туда же, а само
  расширение включается в общем конфиге.
- **Тестовый коммит с другим автором** — настройка на одну команду:
  `git -c user.name=… -c user.email=… commit`.
- **Эксперименты с git** (хуки, настройки, история) — `git clone` во
  временную папку, не в общем репозитории.
- **После коммита** — `git log -1 --format=%ae`: автор тот, кто должен быть.
  Чужой — сначала `git config --show-origin user.email`: откуда он взялся, а
  не правка на ощупь.
