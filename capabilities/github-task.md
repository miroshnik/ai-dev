# github-task

Скилл `github`, `task new`, `task status` и `task drop`: задачу заводят, двигают по доске и закрывают одной
командой, и она всё время по канону `AGENTS.md`.

Заведённая руками задача остаётся без статуса, приоритета или связи с эпиком — и выпадает с доски и из оценки
эпика. Команда ставит всё сразу: тип или метку, проект и `Бэклог`, `Priority`, эпик, blocked by, milestone, а
проверяет всё до создания — задача не появляется наполовину. Статус подзадачи тянет за собой эпик, закрытая без
выполнения уходит из проекта.

Метка решения ставится при создании: по ней задачу находят из спеки, а `est` — аналоги по тому же решению.

<details><summary>✅ 4 теста</summary>

- ✅ метка не решения, которой нет в репозитории, — ошибка до создания задачи

## pr labels ставит задаче метки решений по диффу PR, эпику — объединение

Метки решений задачи ставит её PR: какие папки спеки и модули модели он меняет, те решения задача и трогала.
Эпик копит метки подзадач — по нему видно, каких решений касается вся большая задача.

<details><summary>✅ 7 тестов</summary>

- ✅ задача из «Closes #N» получает метки решений по папкам спеки в диффе PR
- ✅ изменённый код — метка модуля модели из головы PR, путь модуля — самый длинный подходящий
- ✅ метки решения нет в репозитории — создаётся с цветом вида
- ✅ прежняя метка решения, которого нет в диффе, — не снимается, строка в выводе
- ✅ эпик задачи получает метки подзадачи — объединение
- ✅ связь PR с задачей ещё не появилась — задачи берутся из «Closes #N» в теле PR
- ✅ PR без «Closes #N» — ошибка, ничего не меняется

</details>

## Статус ставится, даже если проект ещё не показал задачу

GitHub добавляет задачу в проект не мгновенно для чтения: ответ createIssue и чтение задачи могут ещё не показывать
элемент, а повторное добавление отвечает «Content already exists». Статус всё равно ставится — по элементу, который
станет виден после короткой паузы.

<details><summary>✅ 3 теста</summary>

- ✅ createIssue ещё не показывает элемент, добавление — «уже есть»: task new всё равно ставит Бэклог
- ✅ задачу проект уже добавил, а чтение её ещё не показывает: task status перечитывает с паузой и ставит статус
- ✅ элемент так и не виден — понятная ошибка с тем, что повторить, а не падение

</details>
