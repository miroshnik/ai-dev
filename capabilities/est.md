# est

Скилл `est`: сколько часов работы агента займёт задача — по фактам похожих закрытых задач, и сколько заняла на
самом деле — часы, токены и стоимость из транскриптов.

Оценка «из головы» ничем не проверяема, поэтому и оценка, и факт здесь измеряются: факт — по сессиям агента,
привязанным к задаче, оценка — по фактам аналогов. Агент выбирает аналоги и объясняет расхождения; скрипт
`est.ts` делает детерминированное — читает транскрипты Claude Code, Codex и облачных сессий, ставит поля
проекта и пишет комментарии «Оценка» и «Факт».

## Факт — активные часы работы над задачей по её сессиям

Факт — активные часы: записи, привязанные к задаче, и паузы между ними не длиннее gap (30 мин); общий PR на
несколько задач делится поровну.

<details><summary>✅ 4 теста</summary>

- ✅ записи на ветке задачи и субагента с подсказкой считаются, паузы ≤ gap — время, токены и цена — с долей
- ✅ общий PR на две задачи — доля ½ на записях ветки, субагент с подсказкой — целиком; в результате есть «shared»
- ✅ сессия на чужой ветке не привязывается — покрытие none, факт недоступен
- ✅ пауза длиннее gap не входит во время

</details>

## Фан-аут задачи — число её субагентов в факте и в истории

Задачу, которую делают параллельные субагенты, часы сжимаются, а токены растут: каждый субагент заново читает
контекст. Число субагентов задачи — признак, по которому подбираются аналоги с тем же фан-аутом.

<details><summary>✅ 2 теста</summary>

- ✅ число субагентов задачи — в факте, в комментарии и в маркере; субагенты другой задачи не в счёт
- ✅ история показывает число субагентов задачи; у факта без признака — прочерк

</details>

## Сессия, которая ведёт задачи подряд, делит время между ними

Одна сессия может вести несколько задач подряд: её переименовывают под каждую следующую. Записи на ветке без
номера задачи (её назвал инструмент worktree) достаются задаче из названия сессии на момент записи: первое
название действует с начала сессии, каждое следующее — с переименования. Одна запись — одной задаче.

<details><summary>✅ 7 тестов</summary>

- ✅ записи безномерной ветки достаются задаче из названия на момент записи, а не из последнего; ни одна не засчитана двум задачам
- ✅ pr-link смёрженного PR прошлой задачи, повторённый после мержа, не обрывает время следующей задачи
- ✅ окно своего PR не тянется назад через переименование: записи на HEAD под прошлым названием остаются прошлой задаче
- ✅ маркер факта хранит интервалы по сессиям — по ним следующий расчёт видит, что уже засчитано
- ✅ запись, уже засчитанная в записанном факте другой задачи той же сессии, по названию повторно не засчитывается — комментарий называет ту задачу
- ✅ повтор той же записи названия не начинает новый период — переход на другую ветку без номера по-прежнему закрывает окно
- ✅ запись на своей ветке остаётся своей и при пересечении с записанным фактом другой задачи — только предупреждение

</details>

## Хеш в листинге git — якорь, только если коммит сделала сама сессия

Хеш коммита в выводе инструмента привязывает сессию к PR этого коммита. Но канон велит смотреть на соседей
(`git worktree list`, `git branch -a`, `git fetch`), и их вывод перечисляет чужие коммиты — свежие, рядом по
времени. Хеш из такого листинга — якорь, только если этот коммит сделала сама сессия: он есть и в выводе её
`git commit`, `git push` или скрипта.

<details><summary>✅ 4 теста</summary>

- ✅ сессия «#10 …», в выводе которой только листинг с хешем PR задачи #12, отдаёт время #10, а не #12
- ✅ листинг git и чтение через gh дают якорем только коммит из вывода самой сессии; скрипт рядом и gh pr view — как git commit
- ✅ проверка соседей одной командой с циклом for по задачам — листинг: хеш соседнего worktree не якорь
- ✅ цикл или условие с git commit внутри — не листинг: хеш коммита — якорь

</details>

## Сессия из каталога другого репозитория даёт факт задаче только по признакам её репозитория

Разговор в сессии одного репозитория перерастает в задачу другого: задачу заводят там же, сессию переименовывают
«#N …», коммит и PR — в другом репозитории. Такая сессия — гость: её транскрипт лежит в каталоге чужого
репозитория, а номера задач у репозиториев свои. Поэтому гостя привязывают только признаки, в которых есть
репозиторий задачи: её PR и коммиты, точная ветка её PR, URL её issue; номер в названии — лишь вместе с ними.

<details><summary>✅ 5 тестов</summary>

- ✅ сессия из каталога другого репозитория с PR и коммитом задачи даёт ей факт — с переименования под задачу, ветка того репозитория не в счёт
- ✅ та же сессия не даёт факта задаче своего репозитория с тем же номером — период с PR другого репозитория не её
- ✅ номер в названии сессии другого репозитория без признака репозитория задачи — не привязка
- ✅ pr-link PR другого репозитория с тем же номером — не якорь
- ✅ сессия другого репозитория — кандидат, только если в её транскрипте есть имя репозитория задачи

</details>

## PR достаётся задаче, которую он делает, а не той, что упомянута

PR задачи: сильные связи (закрыл, `Closes #N`, номер в ветке, связан вручную) и — только если сильных нет —
слабые, упоминания. Упоминание в PR, который закрывает другие задачи, — не работа над этой: иначе задача без
своего PR получает чужой PR, его время и тип.

<details><summary>✅ 3 теста</summary>

- ✅ PR закрывает другую задачу и лишь упоминает эту — к ней не привязывается
- ✅ PR без закрываемых задач, упоминающий задачу, — слабая связь, когда сильных нет
- ✅ сильная связь — Closes #N или номер в ветке — важнее упоминаний

</details>

### облачная часть в маркере факта

Облачная сессия считает свою часть сама — по своему транскрипту в контейнере — и отдаёт её в комментарии «Факт
(облако)» маркером `cloud`. Поля проекта из облака не поставить: их ставит локальный `est fact --write` / `--sweep`,
складывая облачную часть с локальной. Выгрузка той же сессии, если импортирована, важнее части.

<details><summary>✅ 4 теста</summary>

- ✅ облачная часть считается, как сессия: время, токены, стоимость, покрытие full по трейлеру; в маркере — сохраняется
- ✅ с локальной работой той же поры — сумма без двойного счёта пересечения
- ✅ выгрузка той же сессии импортирована — часть из маркера второй раз не считается
- ✅ части собираются из всех комментариев с маркером факта; по сессии — последняя

</details>

## Комментарии «Оценка» и «Факт» обновляются на месте, строки человека сохраняются

Комментарии «Оценка» и «Факт» кончаются машинным маркером `<!-- est {…} -->` или `<!-- fact {…} -->`: по
нему скрипт находит свой комментарий и обновляет его, а не пишет новый. Строки, дописанные человеком,
переживают перезапись.

<details><summary>✅ 4 теста</summary>

- ✅ маркер \<!-- est {…} --> читается, битый JSON — как отсутствие
- ✅ «+ вручную: N ч» и «Причина: …» сохраняются при перезаписи комментария
- ✅ текст с часами, отношением к оценке, PR и диффом; маркер разбирается обратно; строки человека сохранены
- ✅ без сессий — «Факт недоступен» и покрытие none в маркере

</details>
