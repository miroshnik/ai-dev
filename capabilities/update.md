# update

Проверка и обновление флоу: агент первым шагом сессии узнаёт, не отстали ли правила и скиллы от последнего релиза
ai-dev, и одной командой доводит их до актуальных — чтобы сессия работала по текущим правилам, а не по когда-то
поставленным.

Правила грузятся в контекст на старте сессии, поэтому `ai-dev check` идёт первым (AGENTS.md): он ничего не меняет и
отвечает кодом 0 — актуально, 1 — отстаёт, 2 — проверка недоступна. `ai-dev update` обновляет: копию —
переустановкой, клон — `git pull`. Файл флоу, который игнорирует git проекта, — тоже несоответствие (код 1, `❌`
с правилом): чужой чекаут и облачная сессия его не получат; исключение в `.gitignore` допишет тот же `update`.

Копия (проект, машина без `--link`) следует за релизами, а не за main: сверять её с main значило бы делать все
проекты «отставшими» на каждом коммите в правила — пилотный проект за пять дней ставил флоу девять раз, и каждое
обновление переделывало уже перенесённое. Команда осталась прежней: пакет, который npx берёт из main, находит
последний тег релиза и перезапускается из него, так что и код, и файлы — релиза. Спецификатор npm
`github:…#semver:x` отвергнут: он требует semver-тегов, кавычек в zsh, а команда без него молча ставит main.
Релизов ещё нет — работает сам, как раньше. Клон `--link` владельца остаётся на `origin/main` — правки видны сразу —
и напоминает строкой «не в релизе», что проекты их ещё не получили.

## Копия следует за релизами ai-dev, а не за main

Проекты и машина копией следуют за релизами ai-dev (теги vГГГГ.ММ.ДД), а не за main: коммит в main без релиза их
«отставшими» не делает. Пакет npx из main находит последний релиз и перезапускается из него — дальше и код, и
файлы релиза.
