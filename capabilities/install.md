# install

Установка флоу: одна команда `npx github:miroshnik/ai-dev install` даёт проекту общие правила, справочники и все
скиллы последнего релиза ai-dev для любого агента; с `-g` машина получает только скиллы и хук.

В проекте всё ложится копией в `.agents/` и коммитится: облачная сессия и CI видят ровно ту версию, что агент
у разработчика. Claude Code получает симлинки из `.claude/`, остальные агенты — ссылку в `AGENTS.md` проекта. На
машине правил нет — их грузит проект, а вторая копия читалась бы на каждом ходу; там `~/.agents/skills` и
скиллы с хуком агентам, которые на ней есть.

Вести ли задачу целиком без спроса — отвечать на её вопросы по рекомендации, коммитить, пушить, чинить CI и мержить
свой PR по зелёным чекам — решение проекта, а не флоу: `install` спрашивает об этом в терминале и хранит ответ в
`.agents/ai-dev.json` (`auto`) — его видят облачная сессия и любой агент. По умолчанию «нет»: молчание не даёт
права на необратимое. В клон ai-dev флоу не ставится — канон в его корне; `install` пишет в нём только эту
настройку.

Копия коммитится, поэтому установка следит, чтобы git проекта её не игнорировал: шаблон `CLAUDE.md` (личные заметки
агента прячут часто), каталог `.claude/` или `vendor/` молча оставляют файл флоу вне коммита, а закоммиченный симлинк
`.claude/rules` — ведущим в пустоту в чужом чекауте и облачной сессии. Исключения пишутся блоком ai-dev в конце
`.gitignore` — отрицание действует, только если идёт после игнорирующего правила; каталог снимается цепочкой
`!/.claude/`, `/.claude/*`, … ровно с файлов флоу, прочее в нём игнорируется, как раньше. Каталог, исключённый личным
правилом (core.excludesFile), — `❌` без исключения: `/.claude/*` в проекте спрятал бы прочее в нём у всех.

Мерж без ревью человека приложение Claude Code отклоняет и при `auto`: его разрешает правило `Bash(gh pr merge *)`
в настройках разрешений машины, а оно действует на все её репозитории — шире проекта. Такое разрешение владелец
ставит своей рукой: `install` с auto правило называет, настройки машины не меняет — иначе о нём узнают из отказа в
конце первой задачи.

## Файлы флоу не игнорируются git проекта — иначе их нет в коммите, чужом чекауте и облачной сессии

Копия флоу коммитится: облачная сессия, чужой чекаут и CI видят только репозиторий. Шаблон из .gitignore проекта
(`CLAUDE.md` — частая практика прятать личные заметки агента, `.claude/`, `vendor/`) молча оставляет файл флоу вне
коммита, а закоммиченный симлинк `.claude/rules` — ведущим в пустоту. Исключение действует, только если идёт после
игнорирующего правила, — поэтому блок ai-dev в конце `.gitignore`.

<details><summary>✅ 5 тестов</summary>

- ✅ шаблон CLAUDE.md в .gitignore проекта — install дописывает в конец .gitignore блок ai-dev с исключением: копия claude/CLAUDE.md не игнорируется, свои строки .gitignore на месте, повторная установка блок не дублирует
- ✅ каталог .claude/ в .gitignore проекта — исключения снимают его только с файлов флоу: правила и скиллы не игнорируются, свои файлы в .claude по-прежнему игнорируются
- ✅ игнорируются .agents/ и vendor/ — после install ни один файл флоу не игнорируется, свои vendor/ проекта и прочее в .agents игнорируются
  > `vendor/` — у скилла spec есть `scripts/vendor`: шаблон внутри скилла снимается уже после исключения на `.agents`.
- ✅ ничего не игнорируется — .gitignore не создаётся и не меняется; ставший ненужным блок убирается
- ✅ шаблон файла вне проекта (core.excludesFile) снимается исключением в .gitignore проекта; каталог, исключённый вне проекта, — ❌ с правилом, исключений на него в .gitignore проекта нет
  > Личные правила (core.excludesFile, `.git/info/exclude`) — не проекта. Исключение файла безвредно для всех, а
  > исключение каталога с `/<каталог>/*` спрятало бы остальное в нём у тех, у кого такого правила нет.

## Задача целиком без спроса — настройка проекта, по умолчанию «нет»

Commit, push и мерж необратимы, поэтому по умолчанию они — по «да» владельца. Проект может разрешить агенту вести
задачу целиком самому: ответ хранится в манифесте проекта, а не на машине — его видят облачная сессия и любой
агент. Сам вопрос в терминале тестом не покрыт: псевдотерминала без зависимостей у Node нет.

<details><summary>✅ 4 теста</summary>

- ✅ без терминала и без флага вопроса нет — у новой установки в .agents/ai-dev.json auto: false
- ✅ --auto пишет auto: true, повторный install без флага его сохраняет, --no-auto возвращает false
- ✅ install -g настройку не спрашивает и не хранит — в ~/.agents/ai-dev.json поля auto нет
- ✅ в клоне ai-dev install флоу не ставит — пишет в .agents/ai-dev.json только auto: с --auto — true, без флага и терминала — прежнее значение
  > Клон ai-dev — сам канон: правила в его корне, копия флоу в нём — лишняя. Режим у него свой, как у проекта.

</details>

## Мерж своего PR в Claude Code — правило разрешений владельца: install с auto подсказывает, а не ставит

`auto` — настройка проекта, а мерж без ревью человека в Claude Code решают настройки разрешений машины: правило
`Bash(gh pr merge *)` действует на все её репозитории. Разрешение шире проекта владелец ставит своей рукой —
`install` его называет, а не пишет: иначе владелец узнаёт о правиле из отказа в конце первой задачи.
