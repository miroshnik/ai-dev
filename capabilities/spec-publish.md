# spec-publish

Скрипт `spec-publish` скилла `spec`: после мержа в `main` CI публикует сгенерированную документацию `docs/spec` в
отдельную ветку `spec`, а не коммитит её в `main`.

`docs/spec` — производная копия тестов: в `main` параллельные PR конфликтовали бы в сгенерированных страницах и
оглавлении. Ветка `spec` читается в GitHub и агентом (`git show origin/spec:README.md`), каждая публикация помнит
SHA `main`, из которого собрана, и CI проверяет, что опубликовано ровно то, что собрано.

Без CI на `main` публикуется `docs/spec` из прогона CI головы PR, а находит его скрипт `spec-run` по исходу прогона:
выдача `gh run list --status success` отстаёт от завершения прогона на минуты, и публикация сразу после мержа падала
с «нет успешного прогона», хотя прогон давно прошёл. Идущий прогон ждём, упавший — ошибка сразу: ждать нечего.

## Документация публикуется в ветку spec, а не коммитится в main

- ✅ повтор без изменений — без нового коммита; изменение — новый коммит поверх, история публикаций сохраняется
- ✅ удалённая страница исчезает из ветки

## --check сверяет опубликованное с собранным

Проверяю то, что дошло до читателя: ветка на «GitHub», а не свой вывод.

<details><summary>✅ 2 теста</summary>

- ✅ ветка совпадает с docs/spec — код 0; отстала или её нет — код 1 и что не совпало
- ✅ нет каталога docs/spec — код 2 и подсказка собрать его spec-doc

</details>

## Без CI на main прогон CI головы PR находится по исходу, а не по отстающему списку

Без CI на `main` `docs/spec` берётся из артефакта прогона CI головы PR (`ci.md`, «Без CI на main»). Выдача
`gh run list --status success` отстаёт от завершения прогона на минуты: публикация сразу после мержа его не видела и
падала, ветка `spec` отставала до следующего мержа. Поэтому прогон ищется без фильтра по статусу, по его исходу.

<details><summary>✅ 5 тестов</summary>

- ✅ прогон CI головы PR находится, даже если список прогонов по статусу отстаёт
- ✅ из нескольких прогонов на голове PR берётся успешный
- ✅ прогон CI головы PR ещё идёт — публикация ждёт его завершения
- ✅ прогон CI головы PR завершился неуспешно — ошибка с исходом прогона, без ожидания
- ✅ прогона CI на голове PR нет — ошибка по потолку ожидания

</details>
