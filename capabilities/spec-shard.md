# spec-shard

Скрипт `spec-shard` скилла `spec`: шард CI получает тестовые файлы по длительностям прошлого зелёного прогона, а не
по числу тестов.

Флаг раннера `--shard` на время не смотрит. Playwright делит сьют подряд по числу тестов в порядке путей, Vitest —
файлы по хешу пути. Тяжёлые тесты одной папки достаются одному шарду: PR ждёт его, остальные простаивают. В проекте на
флоу шарды Playwright с равным числом тестов расходились по времени больше чем вдвое.

Раскладка жадная: файлы от самого долгого — в самый лёгкий шард. Длительности — из тех же отчётов, что читает
`spec-doc` (JSON Vitest, JSON Playwright, JUnit `bun test`): шаблон CI уже собирает их артефактом `spec-reports` джоба
`spec`, а `spec-run --artifact` находит последний зелёный прогон с ним. Файл длительностей в репозитории отвергнут:
он устаревает и требует коммитов. Нет отчёта — первый прогон, артефакт истёк — файлы делятся поровну по числу; новый
файл без замера получает среднюю длительность.

Источник длительностей один на все шарды прогона. «Последний зелёный прогон» меняется, пока шарды доходят до шага:
прогон другого PR, завершившийся между их запросами, давал шардам разные раскладки — в проекте с тремя шардами e2e 22
файла из 101 не прошли нигде, и CI остался зелёным. Поэтому в Actions `spec-run` берёт прогон, зелёный к началу первой
попытки текущего, — тот же ответ получает и повтор упавших шардов. Отдельный джоб, который выбирает прогон один раз и
отдаёт его шардам, отвергнут: каждый шард стартовал бы позже на время этого джоба. Сбой запроса — красный шард, а не
раскладка по числу рядом с раскладками по длительностям.

Файлы шарда уходят раннеру позиционными аргументами вместо `--shard`, а это фильтры: у Playwright — регулярные
выражения по абсолютному пути, у Vitest — подстроки пути. Путь, который входит в другой путь (`tests/a.test.ts` в
`packages/web/tests/a.test.ts`), взял бы чужой файл: тот прошёл бы в двух шардах или ни в одном. Поэтому фильтр
Playwright экранирован и привязан к концу пути, а файлы, чей фильтр всё же берёт другой файл, идут в один шард.
Проект-зависимость Playwright (вход перед тестами) фильтры не режут: раннер добавляет его в каждый шард сам.

Единица раскладки — файл: файл дольше доли шарда остаётся пределом, его делят на файлы.

## Длительности — из отчётов последнего зелёного прогона

Отчёты прошлого прогона — артефакт `spec-reports` джоба `spec`: слитые отчёты раннеров. Он выкладывается, только
когда тесты прошли, но исход прогона доказывает отдельный запрос: `spec-run --artifact` берёт новейший прогон этого
репозитория с исходом `success` и не ждёт идущий — до его исхода берётся прошлый зелёный.

- ✅ зелёного прогона с отчётами нет — код 0, stdout пуст, причина в stderr: шарды делятся по числу
- ✅ отчёты прогона из форка и истёкшие не берутся

## Шарды одного прогона берут длительности из одного прогона

«Новейший зелёный прогон» — не постоянная: между запросами шардов одного прогона может завершиться зелёным прогон
другого PR. Шарды тогда раскладывают файлы по разным отчётам, раскладки расходятся: одни файлы идут в двух шардах,
другие — ни в одном, и CI зелёный без них — в проекте с тремя шардами e2e так пропало 22 файла из 101. Поэтому в
Actions источник — новейший прогон, зелёный к началу первой попытки текущего (`GITHUB_RUN_ID`): ответ один, когда бы
шард ни дошёл до шага. Сбой запроса — красный шаг: шард, разложенный по числу рядом с шардами по длительностям,
терял бы файлы так же.

- ✅ повтор упавших шардов (попытка 2) берёт источник первой попытки: прошедшие шарды первой попытки не перекладываются
