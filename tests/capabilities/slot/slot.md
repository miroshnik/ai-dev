Скилл `slot`: тяжёлые прогоны машины — проверки проекта `lint`, `typecheck`, `test` — идут очередью: одновременно
два, вместе — половина ядер, остальные ждут по порядку прихода и видят, кого ждут.

Параллельные сессии агентов — при раздаче эпика их до двадцати в одном проекте — гоняют полную проверку разом, а
каждый раннер рассчитан на всю машину. По транскриптам за две недели: пик — 23 тяжёлых прогона одновременно, 33
прогона оборвал 10-минутный таймаут инструмента, тот же набор тестов шёл 5 с в одиночку и 35 с при десятке соседей.
Правило «под нагрузкой — перезапуск после соседей» неисполнимо: узнать, когда соседи закончат, нечем, и сессии
повторяли прогон, добавляя нагрузку. Очередь даёт то, чего не было: прогон стартует, когда есть место, и выходит
таким же быстрым, как в одиночку.

Два слота по четверти ядер, а не один на половину: `lint` и `typecheck` обычно однопоточны, и два прогона по
четверти проходят очередь быстрее одного на половину. Сколько воркеров взять, раннер узнаёт из
`AI_DEV_SLOT_CPUS`; вторая половина машины — человеку, приложению и самим агентам.

Слот — файл-билет в `slots/` каталога личной конфигурации с PID процесса в имени. Процесс умер, даже убитый без
уборки, — его билет не в счёт и убирается первым, кто его увидит: замков, которые надо снимать руками, нет.

Песочница агента каталог конфигурации на запись не открывает, а проверки в ней идут без отключения песочницы — иначе
каждая просит разрешения. Билет тогда — в `ai-dev/slots` временного каталога: в песочнице Claude Code он общий для
всех сессий пользователя. Очередь читается из всех мест сразу, включая временный каталог Claude Code
(`CLAUDE_TMPDIR` — он есть и вне песочницы): прогоны в песочнице и вне её (`github pr premerge`, команда с
отключённой песочницей) ждут друг друга. Терминал человека этот каталог не знает и прогоны песочницы не видит —
человек запускает тяжёлое редко. Места для билета нет нигде — одна строка предупреждения и команда без очереди:
проверка без очереди лучше, чем никакой. Отвергнуто: расширять песочницу из установщика (запись в
`~/.config/ai-dev`) — граница песочницы решается владельцем, а не скриптом.

Без очереди — в CI, где машина отдана прогону, и внутри слота: скрипт, который зовёт другой скрипт из очереди,
иначе ждал бы сам себя. Аргументы дописываются в конец команды, как у `npm run`, — обёрнутый скрипт принимает
путь к файлу теста так же, как без обёртки.

Обёртка — `bun --no-env-file`: Bun сам подгружает env-файлы рабочего каталога (`.env`, `.env.local`), а slot
передаёт своё окружение команде — прод-ключи из `vercel env pull` дошли бы до раннера тестов, который без обёртки их
не видел: тесты «ключ не задан» краснели локально и были зелёными на CI. С флагом команда получает то же окружение,
что и без обёртки; раннер, который подгружает env-файлы сам (`bun test`), подгружает их как прежде. Отвергнуто:
`env = false` в `bunfig.toml` проекта — отключил бы env-файлы и собственным `bun test`, `bun run dev` Bun-проекта
(tests/standards/no-env-file).

Отвергнуто: хук Claude Code, переписывающий команды, — ловит только Claude и держится на регулярках, а скрипт
`package.json` зовут все, включая человека в терминале; правило без механизма — его уже не исполняли; лимит
сессий — думать и править код дёшево, мешают только тяжёлые прогоны; пониженный приоритет (`nice`) — интерфейсу
легче, но прогоны всё равно душат друг друга и упираются в таймауты.
