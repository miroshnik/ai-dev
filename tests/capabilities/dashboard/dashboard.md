Скилл `dashboard`: страница в браузере, где по времени видно, сходятся ли оценки задач с фактами и падает ли цена
задачи, — чтобы править флоу по цифрам, а не по ощущению.

Флоу меняется ради двух величин: точности оценок и стоимости задачи. `est history` показывает их таблицей — отдельные
задачи видны, тренд нет. Дашборд берёт те же данные (поля проекта GitHub и маркеры комментариев «Оценка» и «Факт»,
через скрипт `est` рядом) и рисует их по дате закрытия задачи; в GitHub ничего не пишет.

## Почему один график из четырёх панелей

Часы, токены и доллары — разные единицы. На одной панели с двумя шкалами их взаимное положение произвольно: график
рисует связь, которой в данных нет. Поэтому панели отдельные, ось времени общая, шкала значений у каждой своя — и
логарифмическая: задачи различаются в десятки раз, а точность оценки — отношение, на такой шкале ×2 выше и ×2 ниже
одинаково далеки от оценки.

Четвёртая панель — факт к оценке: на панели часов оценка и факт сотни задач — пары точек, сходятся ли они, по ним
не прочесть. Отношение с линией ×1 и полосой допуска ×0,5…×2 отвечает на этот вопрос прямо, а его тренд — это k
во времени.

Точка — задача, линия — скользящая медиана последних 10 задач: задачи разного размера, среднее тянет одна большая.
Оценка идёт только с маркером `est` — старые оценки в других единицах, как и в k. Эпик в график не входит: его часы
— сумма подзадач, они уже на графике.

## Почему доля стоимости по моделям

Стоимость задачи — флоу, умноженный на тариф модели: смена модели меняет её в разы при том же флоу, и тренд
стоимости этого не отличает. Плитка «Стоимость по моделям» показывает долю $ каждой модели у последних задач и у
предыдущих — сдвиг тарифа виден рядом с трендом, а эффект флоу читается по токенам и часам.

## Почему страница рисуется на сервере

SVG собирается строкой в скрипте — геометрию проверяет `bun test`, без браузера, зависимостей и CDN. В браузере
остаётся только подсказка при наведении; всё, что она показывает, есть и в таблице под графиком.

Сервер слушает только `127.0.0.1` и отвечает только на своё имя: страница называет задачи непубличных
репозиториев, а сайт, навёдший своё имя на `127.0.0.1` (DNS rebinding), читал бы её из браузера пользователя.

Отказ `listen` Bun отдаёт как `EADDRINUSE` на любом порте — и когда порт занят, и когда слушать запрещено (песочница
агента). «Порт занят» скрипт пишет, только если свободный порт взять можно, иначе — что локальный порт здесь не
открыть: на «port 0 is busy» агент перебирал порты, вместо того чтобы запустить сервер вне песочницы.

Отвергнуто: подкоманда `est dashboard` — графиков станет больше, а `est.ts` уже велик; файл HTML без сервера —
данные устаревают в момент записи, а страница с сервером перечитывает проект при открытии.

## Вкладка «Сессии» — главная

При двух-трёх десятках параллельных сессий владелец спрашивает одно и то же: «не зависло ли?», «что с этой
сессией?», «что за задачи висят?» — и отвечает себе обходом сессий руками; вопросы к нему разбросаны по ним. Поэтому
страница открывается вкладкой «Сессии»: строка на задачу «В работе» — её сессия и чего та ждёт, сверху — «Ждут
владельца». График оценок — вторая вкладка: его смотрят после правки флоу, а сессии — каждый час.

Сессия задачи — по файлу закрепления `github task status` (`sessions/<id сессии>` каталога конфигурации), а не по
эвристике названия или ветки: закрепление пишется в момент взятия задачи и однозначно. Чего сессия ждёт — по её
транскрипту: фоновая задача без уведомления о завершении (её разбудит уведомление), последний ход — ответ без вызова
инструмента (ход за человеком), записей нет дольше 15 мин (тишина); что именно ждёт фоновая — CI или деплой, — видно по
PR задачи. Транскрипт — единственный источник, который пишет само приложение: статус, который ставила бы модель,
врал бы ровно тогда, когда сессия зависла.

GitHub для вкладки — запрос на репозиторий без блокировки сервера, задачи «В работе» — фильтром проекта на стороне
GitHub: строки проекта целиком, с комментариями, по всем репозиториям читаются десятки секунд, а вкладка обновляется
сама каждые 30 с. Устаревший кэш отдаётся сразу, свежий собирается в фоне. Обновление — подменой `<main>`, а не
перезагрузкой: перезагрузка сворачивала бы раскрытые вопросы каждые полминуты.

Вопросы сессии без задачи «В работе» — только явные (строки конца сессии или абзац на «?»), рутины по расписанию не в
счёт: на настоящих сессиях блок без этого тонул в ответах вроде «за час заявок не было». Задачи бэклога с меткой
«вопросы» свёрнуты группой — их десятки, и они ждут, пока задачу возьмут, а не сейчас.

Отвергнуто: облачные сессии — их транскрипт в облаке, а проекты GitHub им закрыты, задачу они не закрепляют; видно
только, что PR задачи сделан облаком. Статус «тишина» по одному времени без фоновых задач — фоновое ожидание CI
молчит по полчаса и было бы ложной тревогой.

## Адреса сервисов задачи

У задачи «В работе» свой стек Docker Compose и свои адреса `<сервис>.<N>.<проект>.localhost` (скилл `task-env`), но
их надо знать: владелец открывает приложение задачи с дашборда одним кликом, а не собирает адрес из номера и имени
репозитория. Источник — маршруты прокси из его API по loopback, а не сокет Docker: доступ к Docker — доступ ко всей
машине, а маршрутам нужен только loopback. Маршрут появляется со стартом контейнера и пропадает с его остановкой — поэтому маршруты
читаются при каждом открытии вкладки, как закрепления, а не раз в минуту, как GitHub. Схему адреса знает скрипт
`task-env` (`taskAddress`, `hostProject`, `addressUrl`), дашборд её не повторяет.

Где запускать дашборд, замерено на macOS (#396): без `sandbox.network.allowLocalBinding` песочница Claude Code не
даёт слушать порт; с ней сервер слушает и читает маршруты прокси, но `gh`, которого скрипт запускает, в песочнице
не проходит проверку TLS (`x509: OSStatus -26276`), и вкладка остаётся без задач — запись `gh *` в
`excludedCommands` выводит из песочницы прямой вызов, а не дочерний процесс скрипта. Поэтому дашборд запускается вне
песочницы, а `allowLocalBinding` нужна его тестам, которые поднимают свои серверы с подставным `gh`.

Адреса e2e на вкладку не идут: стек e2e пересоздаётся на каждый прогон, ссылка на него живёт минуты (#396, вопрос 4).
Прокси не запущен — ссылок нет и ошибки нет: без прокси нет и адресов, а строка в плашке у каждого, кто Docker не
ставил, была бы шумом; любой другой сбой — плашкой, как ошибка GitHub (вопрос 5).
