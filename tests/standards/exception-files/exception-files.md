Файл исключений папки решения (канон spec: «Исключения — только в `exceptions/` папки решения») каждый скрипт
распознаёт одинаково: на вопрос «файл исключений какой папки решения?» харнесс, `spec-doc`, `spec-diff` и
`spec-exceptions` отвечают одно и то же, `github pr labels` по тому же ответу решает, механическая ли правка.

Харнесс по ответу читает исключения и падает на файле не на месте, `spec-doc` — исключения названий, `spec-diff`
показывает их в разделе «Исключения» тела PR, `spec-exceptions` переносит прежний файл в каталог, `pr labels` не ставит
за правку исключений метку решения. Четыре копии правила расходились на краях: `exceptions.mts` харнесс считал
прежним файлом исключений, а `pr labels` — правкой решения; `spec-exceptions` переносил `exceptions.ts` подпапки в
каталог подпапки, которого `exceptionsIn()` её тестов не читает, — исключения терялись. Ошибка копии видна поздно:
лишняя метка у PR разбора долга, исключение, которого нет в теле PR, перенос, после которого исключения не читаются.

## Правило

Папка решения — `tests/<вид>/<имя>`, вид — `capabilities`, `architecture`, `standards`.

- `<папка>/exceptions/<элемент>.json` — исключение папки, `<папка>/names.exceptions/<название>.json` — исключение
  названия (`spec-doc`);
- иной файл в каталоге — не `.json` или во вложенном каталоге — ошибка: исключение — JSON-файл;
- каталог `exceptions/` (`names.exceptions/`) в подпапке папки решения — ошибка «только в `<папка>/exceptions/`»:
  каталог один на папку, его читает `exceptionsIn()` теста любой подпапки;
- `exceptions.{ts,mts,js,mjs,json}` (`names.exceptions.*`) в папке или её подпапке — прежний формат исключений
  папки: харнесс и `spec-doc` падают с подсказкой `spec-exceptions`, тот переносит файл в каталог папки;
- скрытые файлы (`exceptions/.gitkeep`) и файлы вне папок решений (`tests/lib`, `src`) — не исключения.

Механическая правка в `pr labels` — файл, который spec читает исключением: ответ — папка без ошибки.

Внутри скилла spec правило одно — `exceptionFile` в `speclib.ts`; харнесс, `spec-doc`, `spec-diff` и
`spec-exceptions` его импортируют. Между скиллами — копия в `github`: скиллы ставятся по одному, `github` работает без
`spec`, импорт между скиллами это сломал бы. Реестр — скрипты скиллов, которые определяют `exceptionFile`, зовут его
или сами знают пути исключений (регулярка про `exceptions`, имя прежнего файла, путь `…/exceptions`). Копия отвечает
по одной таблице; остальные своего знания путей иметь не должны. Голое слово `"exceptions"` в коде — не знание пути:
так же называются поле и переменная.
