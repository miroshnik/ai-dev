Флоу переименован в Elves (эпик #542), а установки переходят по одной: проект с копией прошлого релиза, машина до
`update -g`, профиль владельца с переменной `AI_DEV_*`. Поэтому старое имя `ai-dev` (и `AI_DEV_*`) в файлах флоу
остаётся только там, где оно читается для перехода, — и решение там одно: старое имя узнаётся своим и заменяется
новым, второго нет. Манифест `update` переносит, а не копирует; блок в `AGENTS.md` заменяет на месте; хук со старой
командой узнаёт своим и не ставит второй; скрипт до переноса читает прежний манифест, но новый, если есть, — первым.

Решение живёт в скриптах своими константами в каждом: общего модуля нет — скрипт скилла не импортирует другие скиллы
(стандарт `skill-imports`), и прежний манифест читают три скрипта тремя константами. Без проверки «готово» эпика —
ручной grep, а старое имя возвращается по привычке: агенты знают `.agents/ai-dev.json` и `~/.config/ai-dev` из памяти
и транскриптов, а скрипт, который после переноса читает только старый путь, молча работает без конфигурации — без
языка, режима auto, `env.http`.

## Правило

Реестр имён для перехода — места в тесте стандарта. У каждого места — файл и блок, что под старым именем узнаётся и
тест, который держит переход: старое имя узнаётся своим, заменяется, второго нет. Инвариант — в файлах флоу (`bin/`,
`skills/`, канон `AGENTS.md` и `claude/`, `docs/`, `README.md`, `package.json`) `ai-dev` и `AI_DEV_` в любом регистре
встречаются только в местах реестра; путь файла — тоже (`bin/ai-dev.ts`).

Место — блок, а не файл: в установщике старое имя законно в константе прежних имён `FORMER`, а новая функция, которая
читает `.agents/ai-dev.json` мимо неё, — то самое возвращение по привычке. Блок кода — объявление верхнего уровня с
его комментарием, комментарий перед импортами — `header`; блок документа — абзац с фразой места или раздел под его
заголовком; в JSON — путь ключа; файл, который существует только ради перехода, — место целиком. Комментарий и
справочник рядом с константой называют её (`FORMER.manifest`, `FORMER_PROXY`), а не повторяют старое имя: копия
разошлась бы с константой, и место было бы вторым.

Реестр не копит мёртвых мест: место, где старого имени больше нет (переход снят, константа переехала), — красный тест
«убери из реестра»; тест перехода, переименованный или удалённый, — тоже красный: место без теста ничего не держит.

Выражение каталога личной конфигурации (`AI_DEV_CONFIG_DIR`, `~/.config/ai-dev`) — место реестра со ссылкой на
стандарт `config-dir`: форму выражения держит он, второй проверки здесь нет. Места `task-env` с записанным сроком
«один релиз» (прокси `ai-dev-proxy`) снимает #564 — вместе с их строками реестра.

## Что — история, а не переход

Старое имя остаётся в истории, и её не переписывают: история git и сообщения коммитов, теги и списки изменений
релизов, закрытые задачи и PR, опубликованная спека. Тесты (`tests/`) — вне охвата: они моделируют установки до
переименования, и старое имя в них — данные, а описания решений называют переход. Папка локального клона не
переименовывается: по её пути Claude Code хранит транскрипты сессий, из которых `est` берёт факт, и память.
