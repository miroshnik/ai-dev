# dashboard — сессии в работе, оценка, факт и цена задач

При двух десятках параллельных сессий не видно, какая чем занята и чего ждёт,
а вопросы к владельцу разбросаны по сессиям. Флоу же правят ради двух
величин: точности оценок и стоимости задачи, а таблица `est history`
показывает задачи по одной, без тренда. Скрипт `scripts/dashboard.ts`
поднимает страницу в две вкладки:

- **«Сессии»** (`/`, главная) — задачи «В работе», их сессии и чего каждая
  ждёт, сверху — «Ждут владельца»;
- **«Оценка и факт»** (`/est`) — график по дате закрытия задачи: поля проекта
  GitHub и маркеры комментариев «Оценка» и «Факт».

В GitHub ничего не пишет.

```bash
bun <каталог скилла>/scripts/dashboard.ts [--repo o/r | --all-repos] [--since 90d] [--port N] [--no-open]
```

Каталог скилла — тот, где лежит этот файл (у Claude Code —
`${CLAUDE_SKILL_DIR}`). Данные читает скрипт `est` рядом
(`../est/scripts/est.ts`) — скиллы ставятся вместе. Нужен `gh` со scope
`project`, как для `est`. Сессия задачи — по файлу закрепления, который пишет
`github task status <N> "В работе"` (`~/.config/ai-dev/sessions/<id сессии>`
или в `$AI_DEV_CONFIG_DIR`), её состояние — по транскрипту
`~/.claude/projects/<каталог>/<id>.jsonl`.

## Как запускать

Скрипт — сервер: печатает адрес, открывает его в браузере и живёт до
остановки. Поэтому — **фоновой командой**, не обычным вызовом: обычный не
вернётся до таймаута.

1. Перед показом «Оценки и факта» — `est fact --sweep --since 90d --write`
   (скилл `est`): график рисует только записанные факты. «Сессиям» это не
   нужно.
2. Запусти скрипт в фоне и прочитай его вывод: первая строка —
   `дашборд: http://127.0.0.1:<порт>/ — …`, вторая — `браузер: открываю …`
   или `браузер: не открываю (…)`.
3. Назови пользователю адрес. У агента свой браузер (панель приложения) —
   запускай с `--no-open` и открывай адрес в нём; иначе скрипт сам откроет
   системный (`BROWSER=<команда>` — чем открыть, `BROWSER=none` — не
   открывать).
4. Пользователь посмотрел — останови фоновую команду.

| Параметр | Что делает |
|---|---|
| `--repo o/r` | репозиторий; по умолчанию — из `git remote origin` каталога |
| `--all-repos` | все репозитории личного реестра `est` (`~/.config/ai-dev/repos.json`), у задачи назван репозиторий |
| `--since 90d` | период «Оценки и факта» по умолчанию (`d`, `w`, `m`); без него — всё время. На странице — «30 дней», «90 дней», «всё время» |
| `--port N` | порт; по умолчанию — свободный, занятый — ошибка |
| `--no-open` | не открывать браузер |

## Вкладка «Сессии»

- **Строка на задачу «В работе»** проекта (эпик — не строка: его сессия
  планирует): задача и её эпик; сессия — сколько назад была последняя запись
  транскрипта (или субагента), название — если не повторяет задачу; чего
  ждёт — цветной меткой; PR задачи (`Closes #N` или ветка `<type>/<N>-…`) —
  номер, чеки, конфликт, влит и идёт ли деплой. Сверху — ждущие владельца,
  затем молчащие и красные.
- **Чего ждёт.** Фоновая задача сессии (команда, субагент, Monitor) без
  уведомления о завершении — сессия ждёт её: PR открыт и чеки идут — «CI
  идёт», красные — «CI красный», PR влит и идут чеки коммита мержа —
  «деплой», иначе «работает» с описанием фоновой задачи. Последний ход —
  ответ модели без вызова инструмента: «ответ человека», а при зелёном
  вливаемом PR — «мерж»; «Всё сделано. Сессию можно закрывать.» или
  самоархивация — «можно закрывать». Записей нет дольше 15 мин и в фоне
  ничего — «тишина» (вызов инструмента без результата назван: ждёт
  разрешения или завис). Фоновая задача старше 2 ч без уведомления считается
  потерянной. Закрепления нет — «сессии нет»; PR с трейлером `Claude-Session`
  — «облако, состояние не видно»: облачная сессия задачу не закрепляет.
- **«Ждут владельца».** Вопросы из последних ответов сессий задач («ответ
  человека», «мерж»): от строки «Всё сделано, но есть вопросы…» или
  «Осталось: …» до конца ответа, без них — последний абзац. Сессии каталогов
  репозитория (`paths` реестра `est`) без задачи «В работе», писавшие за
  сутки, — только с явным вопросом (эти строки или абзац на «?»), рутины
  (`<scheduled-task>`) не в счёт. Задачи «В работе» с меткой «вопросы» —
  строкой, открытые пункты «## Вопросы» под раскрытием; задачи вне работы с
  меткой — свёрнутой группой.
- Обновляется сама каждые 30 с (и при возврате на вкладку): раскрытое
  остаётся раскрытым. Закрепления и транскрипты читаются заново, GitHub — не
  чаще раза в минуту и в фоне: страница отвечает из кэша, свежее — к
  следующему обновлению.

## Вкладка «Оценка и факт»

- **Сводка.** Точность оценок — k (медиана «факт / оценка» по последним 20
  задачам с маркером `est` и покрытием `full`) и доля задач в допуске
  ×0.5…×2, те же числа, что в `est history`. Часы, токены и стоимость
  задачи — медиана последних 10 закрытых задач и изменение к предыдущим 10.
  Стоимость по моделям — доля $ каждой модели у последних 10 задач и у
  предыдущих 10: сменилась модель — сменился тариф.
- **График** — четыре панели на общей оси времени (дата закрытия): часы
  (кольцо — оценка, точка — факт, отрезок между ними — ошибка), факт к
  оценке (линия ×1 — оценка сошлась, полоса — допуск ×0.5…×2), токены, млн,
  и стоимость, $ (кольцо — прогноз из «Оценки»). Линия — скользящая медиана
  последних 10 задач, число у её конца — текущее значение. Шкалы
  логарифмические: равный шаг — равное отношение.
- **Таблица** — те же значения по задачам, новые сверху; наведение на точку
  подсвечивает строку.

Задачи — закрытые с фактом, как в `est history`; эпик не входит (его часы —
сумма подзадач). Оценка — только с маркером `est`: старые оценки в других
единицах, у таких задач есть факт, но нет кольца и отношения.

## Как читать график

- Оценки сходятся — тренд панели «факт к оценке» лежит у ×1 и точки
  собираются в полосе. Тренд выше ×1 — задачи недооцениваются.
- Задача дешевеет — тренд стоимости и токенов идёт вниз при том же размере
  задач: сверяй с панелью часов и с типами задач в таблице, иначе «дешевле»
  значит «задачи стали мельче».
- Тренд $ смешивает флоу с тарифом модели: смена модели меняет стоимость в
  разы при том же флоу. Плитка «Стоимость по моделям» показывает, сменилась
  ли модель; эффект флоу — по токенам и часам.
- Эффект правки флоу — сравни тренд до и после даты релиза ai-dev (теги
  `vГГГГ.ММ.ДД`) или коммита `chore(agents): флоу ai-dev …` в проекте; десяти
  задач после правки ещё нет — вывод рано делать. Флоу без задач (PR без
  issue) график не видит — его покажет сводка периода по всем сессиям,
  `est period`.

## Подводные камни

- GitHub перечитывается при открытии страницы, но не чаще раза в минуту;
  ссылка «Обновить» — сразу. Ошибка GitHub — на странице, сервер живёт.
- «Оценка и факт» читает строки проекта целиком, с комментариями: по
  `--all-repos` первое открытие вкладки — десятки секунд. «Сессии» их не
  ждут: задачи «В работе» — фильтром проекта на стороне GitHub.
- Задача «В работе» без сессии — `github task status` взят не из Claude Code
  или закрепление снято; две сессии на задачу (после `/clear`) — показана
  писавшая последней.
- Страница локальная: сервер слушает только `127.0.0.1` и отвечает только
  на имена `127.0.0.1` и `localhost`. Наружу её не выставлять — в ней
  названия задач непубличных репозиториев.
- Облачная сессия Claude Code (`CLAUDE_CODE_REMOTE=true`): проекты GitHub
  там закрыты, а её localhost не виден браузеру пользователя — скрипт
  выходит с объяснением (`docs/cloud-sessions.md` в ai-dev).
- Точек мало или нет — у закрытых задач нет факта: `est fact --sweep --write`.
