# github — проект по канону, а не по памяти

Канон проекта — `AGENTS.md`, раздел «Проект (GitHub Projects)». Руками по
справочнику проекты расходятся: где-то выключен «Item closed», где-то фильтр
прячет задачи с доски. Скрипт `scripts/github.ts` рядом с этим файлом
сверяет проект с каноном и чинит то, что умеет API; агент проходит шаги UI и
спрашивает подтверждение на разрушительное.

```bash
bun <каталог скилла>/scripts/github.ts project check [--repo owner/repo]
bun <каталог скилла>/scripts/github.ts project fix [--repo owner/repo] [--confirm] [--template owner/N | none]
```

Репозиторий — из `git remote get-url origin` или `--repo`. Нужен `gh` со
scope `project` (`gh auth refresh -s project`); типы issue организации —
`admin:org`.

## Когда что

| Момент | Действие |
|---|---|
| Начало сессии, перед работой с задачами | `project check` — раз в сессию |
| `check` дал ❌ | `project fix` → шаги UI → подтверждения → снова `check` |
| Репозиторий без проекта | `project fix`: привяжет одноимённый проект владельца, иначе скопирует эталон, иначе создаст |
| Облачная сессия | не запускать: Projects v2 ей недоступны (`docs/cloud-sessions.md`), скрипт выходит с кодом 2 |

Коды: `0` — всё по канону (у `fix` — и шагов не осталось), `1` — есть ❌,
шаги или ошибки, `2` — ошибка вызова, доступа или облачная сессия.

## Что проверяется

1. Проект привязан к репозиторию, он один, название = имя репозитория.
2. Представления `Доска` (BOARD, колонки по `Status`), `Таблица` (TABLE),
   `Роадмэп` (ROADMAP), фильтры пусты, других нет.
3. `Status`: `Бэклог` → `В работе` → `Готово`.
4. Поля «Оценка, ч», «Факт, ч», «Токены, млн», «Стоимость, $» (Number),
   своих полей сверх канона нет.
5. Только организация: `Priority` — поле issue организации, подключено,
   `Таблица` и `Доска` сортируются по нему; типы issue — ровно «Задача»,
   «Баг», «Эпик». В личном аккаунте их нет — строка `➖`.
6. Workflow «Item added to project» (→ `Бэклог`), «Item closed»
   (→ `Готово`), «Auto-add to project» (`is:issue is:open`) включены.
7. Закрытые задачи — в `Готово`, закрытые без выполнения (not planned,
   дубль) — вне проекта.
8. Открытые задачи репозитория — в проекте, у каждой есть `Status`.

## fix: кто что делает

- **API — сам скрипт:** привязка, копия эталона или новый проект,
  недостающие представления и поля, вид представления, снятие фильтра,
  варианты `Status`, поле issue `Priority`, статусы задач, добавление
  открытых задач, удаление из проекта закрытых без выполнения. Строки `+`.
- **Шаги UI** (`Шаги в UI …`) — чего нет в API. Вызов `fix` — разрешение на
  настройку проекта этого репозитория: агент проходит шаги сам, браузером,
  где пользователь вошёл в GitHub (Claude in Chrome или встроенный браузер
  после его входа), без отдельного спроса. Нет браузера или входа — список
  шагов со ссылками пользователю. Пароль агент не вводит. После шагов —
  снова `check`.
- **Подтверждение** (`Нужно подтверждение …`) — удаление и переименование в
  проекте, где уже есть задачи, отвязка лишних проектов, типы issue
  организации (они общие для всех её репозиториев). Показать список
  пользователю, после «да» — `fix --confirm`. В новом проекте без задач
  удаление и переименование идут без подтверждения.
- **Ошибка** — строка `!` с причиной (и ссылкой на UI, если шаг там
  делается): чаще всего не хватает scope у `gh`.

## Шаги UI — как проходить

- **Workflow:** ссылка ведёт на настроенный workflow
  (`<проект>/workflows/<fullDatabaseId>`) или на список `<проект>/workflows`,
  где ненастроенный выбирается в меню слева. Edit → настройка → **Save and
  turn on workflow**; справа вверху появится `On`.
  - «Item added to project»: триггер `issue, pull request` (по умолчанию),
    Set value → `Status: Бэклог`.
  - «Item closed»: Set value → `Status: Готово`.
  - «Auto-add to project»: репозиторий — этого проекта, фильтр
    `is:issue is:open`, Enter — счётчик «See N existing items» должен
    обновиться. Без `is:open` обновлённая закрытая задача (и not planned)
    вернётся в проект. Уже существующие задачи auto-add не добавляет — их
    добавляет `fix`.
- **Сортировка по Priority, колонки доски:** представление → кнопка `View`
  справа → `Sort by: Priority` / `Column by: Status` → сохранить изменения
  представления (`Save`).
- **Поля issue организации** (`Priority` нет в организации) — настройки
  организации по ссылке из шага, затем снова `fix`.

## Детали, из-за которых скрипт написан

- **Workflow через API не включить и цель не прочитать:** `ProjectV2Workflow`
  отдаёт только `name`, `number`, `fullDatabaseId`, `enabled`; мутации
  включения нет. Ненастроенного workflow нет в списке вовсе (у нового
  проекта — «Item closed», «Pull request merged», «Auto-close issue»).
- **Цель «Item closed» видна по результату:** закрытая задача не в `Готово` —
  workflow выключен или смотрит на удалённый вариант `Status`. `fix` ставит
  `Готово` и оставляет шаг проверить цель в UI.
- **Варианты `Status` переименовываются с тем же id**
  (`updateProjectV2Field`, `singleSelectOptions[].id`): значения задач и
  цель «Item closed» сохраняются. Замена вариантов без id даёт новые id —
  статусы задач пропадают, «Item closed» ставит удалённый `Done`.
- **Эталон** — проект ai-dev (`miroshnik/6`): в нём один раз настроено всё,
  чего нет в API. Копия (`copyProjectV2`) переносит представления с
  настройками, поля и настроенные workflow, кроме auto-add; не переносит
  задачи, соавторов и привязку к репозиторию. Эталон недоступен (чужой
  аккаунт) или `--template none` — проект создаётся с нуля
  (`createProjectV2`) и доводится через API: `Todo / In Progress / Done` →
  канон с теми же id, `View 1` → `Таблица`, остальное создаётся.
- **Фильтр представления пуст:** `iteration:@current` без поля Iteration
  молча прячет задачи с доски.
- **`Priority` — поле issue организации** (`isIssueField`), а не своё поле
  проекта с тем же именем. Сортировку API читает (`sortByFields`), но не
  задаёт; группировку доски — тоже (`verticalGroupByFields`).
- **Проект, которым пользовались** — в нём есть задачи.

## Задача в проекте — вручную

Пока задачи не создаются одной командой скилла:

```bash
ITEM=$(gh project item-add <N> --owner <owner> --url <issue-url> --format json --jq .id)
gh project item-edit --id $ITEM --project-id <project-id> --field-id <id-поля-Status> --single-select-option-id <id-варианта>
gh project item-edit --id $ITEM --project-id <project-id> --field-id <id-поля-Оценка> --number 4
gh project item-delete <N> --owner <owner> --id $ITEM        # закрыта без выполнения
gh issue close <N> --reason "not planned"
```

ID проекта, полей и вариантов — `gh project view` / `gh project field-list`
(в JSON `gh project item-list` ключи кириллических полей искажены — не
полагаться на них; скилл `est` ищет поля по точному имени через GraphQL).
