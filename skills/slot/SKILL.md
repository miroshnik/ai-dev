# slot — тяжёлые прогоны машины по очереди

Параллельные сессии гоняют полную проверку разом, а каждый раннер рассчитан на
всю машину: прогон, который в одиночку идёт секунды, при десятке соседей
тянется минутами и обрывается таймаутом инструмента, а повтор добавляет
нагрузки. Скрипт `scripts/slot.ts` рядом с этим файлом пускает одновременно
два тяжёлых прогона, остальные ждут по порядку прихода; вместе слоты берут
половину ядер, вторая — человеку, приложению и самим агентам. Зачем так и что
отвергнуто — `tests/capabilities/slot/slot.md` ai-dev.

```bash
bun <каталог скилла>/scripts/slot.ts '<команда>' [аргументы…]
```

Команда идёт через `sh`, аргументы дописываются в её конец, как у `npm run`;
код выхода — код команды. Без очереди — в CI (`CI`) и внутри слота
(`AI_DEV_SLOT`): скрипт, который зовёт другой скрипт из очереди, иначе ждал бы
сам себя.

## Как включается

Установка флоу (`install`, `update`) оборачивает в `slot` скрипты
`package.json` проекта `lint`, `typecheck`, `test` и `test:*`:
`"test": "node .agents/skills/slot/scripts/slot.ts 'vitest run'"` (у проекта
на Bun — `bun`). Их зовут все — агент, человек в терминале, `github pr
premerge`, — и все встают в одну очередь. `build` не оборачивается — его
запускают хостинг и Docker, где копии скилла может не быть; watch — тоже:
долгий, занял бы слот надолго. Обёртку снял руками — `check` назовёт скрипт,
`update` вернёт.

## Что делает агент

| Момент | Действие |
|---|---|
| Полная проверка перед коммитом, e2e | скриптами проекта (`npm run test`, `bun run typecheck`): они уже в очереди. Фоновой командой с запасом таймаута (Claude Code — `run_in_background`, до 2 ч): ожидание в очереди не съедает таймаут инструмента, завершение будит сессию |
| `slot: жду очередь машины — идут …` | не зависание: кто держит слоты (каталог, команда) и сколько идёт. Чужой прогон не убивать и его билет не удалять |
| `slot: дождался за …` | время в очереди; скорость прогона сравнивать без него — по CI или по `user` у `time` |
| Точечный прогон (`vitest run <файл>`) | мимо очереди — он дешёвый |
| Тяжёлая команда мимо скриптов проекта | `bun <каталог скилла>/scripts/slot.ts '<команда>'` |
| Воркеры раннера локально | из `AI_DEV_SLOT_CPUS` — ниже |

## Воркеры раннера

В слоте команда получает `AI_DEV_SLOT_CPUS` — четверть ядер. Раннер, который
считает воркеры от всех ядер, берёт машину целиком и в слоте; его конфиг
читает переменную, а в CI и вне очереди остаётся при своём:

```ts
// vitest.config.ts
maxWorkers: Number(process.env.AI_DEV_SLOT_CPUS) || undefined,
// playwright.config.ts
workers: Number(process.env.AI_DEV_SLOT_CPUS) || (process.env.CI ? 2 : undefined),
// jest — флагом скрипта: jest --maxWorkers=${AI_DEV_SLOT_CPUS:-50%}
```

## Очередь

Билет на прогон — файл `<время>-<pid>` в `slots/` каталога личной
конфигурации (`$AI_DEV_CONFIG_DIR`, иначе `~/.config/ai-dev`); в нём каталог,
команда и время старта. Кто в очереди — `ls` этого каталога. Процесс умер,
даже убитый без уборки, — его билет не в счёт и убирается первым, кто его
увидит: чистить руками нечего.
